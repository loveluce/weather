# 겹 · GYEOP — GitHub Pages 웹앱 베타

전 세계 도시의 날씨를 확인한 뒤, 체감온도·비·바람·개인 체감·활동량·선택한 겉옷에 맞춰 옷 조합과 소재를 알려주는 모바일 웹앱입니다.

> **중요:** 이 폴더는 GitHub Pages에서 실행하도록 별도로 구성한 **정적 웹 베타 버전**입니다. 이전에 ChatGPT Sites에서 만든 서버형 베타와 완전히 같은 구현이 아닙니다. 자체 계정 가입, 온라인 SNS 피드, 여러 기기의 사진 동기화는 지원하지 않습니다. 사진은 휴대폰/브라우저의 IndexedDB에만 비공개로 저장됩니다.

## GitHub Pages에 무료 공개하기

1. GitHub에서 **New repository**를 누르고 이름을 `gyeop-weather`로 만듭니다. 공개 웹 테스트를 위해 `Public`을 선택합니다. **저장소를 공개하면 소스 코드도 공개**됩니다.
2. 이 ZIP 파일의 **압축을 풀어 내부 파일과 `assets` 폴더를 저장소 최상위에 업로드**하세요. ZIP 자체만 올리면 실행되지 않습니다. 파일은 `index.html`, `app.js`, `logic.js`, `styles.css`, `service-worker.js`, `manifest.webmanifest`, `assets/…` 등입니다.
3. GitHub 저장소에서 **Settings → Pages**를 열고 **Build and deployment → Source: Deploy from a branch**, **Branch: main**, **Folder: /(root)** 를 선택한 후 Save 합니다.
4. 수 분 뒤 다음 형식의 주소가 만들어집니다: `https://<GitHub사용자이름>.github.io/gyeop-weather/`
5. 주소를 아이폰 Safari, 안드로이드 Chrome에서 열고 공유하세요. 모바일 홈 화면에 추가하면 앱처럼 사용할 수 있습니다.

**직접 업로드하는 이유:** 현재 ChatGPT 대화에는 GitHub 계정 쓰기 권한이 연결되어 있지 않습니다. 이 ZIP은 업로드 준비가 끝난 파일입니다. 실제 GitHub 저장소가 생성·게시됐다고 주장하는 파일은 아닙니다.

### GitHub에서 파일 업로드 방법

저장소 첫 화면 → **Add file → Upload files** → 압축을 푼 파일과 폴더를 드래그 → **Commit changes**.

기존 저장소가 이미 있으면 배포 전 다른 프로젝트 코드를 덮어쓰지 않도록 **새 저장소를 권장**합니다.

## 사용 방법

- **오늘:** 도시 선택 → 현재 날씨와 추천 확인 → '추위를 타요', '실내', '패딩' 등을 눌러 추천 변경.
- **여행:** 도시와 출발일/귀국일 선택 → 실제 16일 예보가 존재하는 날에만 날씨별 옷차림 표시 → 개인 체크리스트 만들기.
- **기록:** 사진 촬영/선택 → 추움·적당·더움 중 하나 선택 → 기기 내부에 비공개로 저장. 사진 원본을 전송하지 않고 브라우저에서 JPEG로 다시 만들어 촬영 메타데이터를 제거합니다.
- **설정:** 시작 화면 선택, 기록 내보내기(JSON **사진 제외**), 기록 삭제.

## 안전·개인정보 범위

- 회원 가입이 없으며, 이메일·실명을 앱에서 수집하지 않습니다.
- 착장 사진은 브라우저 IndexedDB에 저장하며 다른 이용자에게 게시되지 않습니다. 서버 업로드와 온라인 커뮤니티 기능은 구현하지 않았습니다.
- 사진 자동 검열·옷 사진 판별·자동 얼굴 블러 기능은 **없습니다**. 개인정보가 담긴 사진이나 다른 사람의 사진을 기록하지 마세요.
- 옷차림 기록은 **기기·브라우저별**로 구분됩니다. 다른 휴대폰에서 같은 주소를 열어도 기록은 보이지 않습니다. 브라우저 기록/사이트 데이터 삭제, 사생활 보호 모드, 저장공간 부족 등의 상황에서 기록이 없어질 수 있습니다.
- 내 위치 버튼을 누르기 전에는 GPS 권한을 요구하지 않습니다. 내 위치 사용 시 약 1km 단위로 반올림한 좌표를 앱 안에 보관합니다. 선택한 도시의 좌표와 접속 IP는 날씨 제공처에 전달될 수 있습니다.
- API 호출 시 `credentials: 'omit'`을 사용합니다. 날씨 응답은 최대 15분간 캐시하며, 최신 조회에 실패하면 24시간 이내의 마지막 자료에 **'최신 아님'** 표시를 합니다. 자료가 없으면 추천을 표시하지 않습니다.

## 날씨 데이터 제공처와 조건

- [Open-Meteo Forecast API](https://open-meteo.com/en/docs)
- [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api)

Open-Meteo의 무료 API는 **비상업·평가 용도**이며 호출량 제한이 있을 수 있습니다. 상업 서비스로 전환하기 전 상업용 API 계약 또는 다른 상용 기상 데이터 소스와의 계약이 필요합니다. 브라우저에서 날씨 API에 직접 접근하므로 국가별 네트워크 정책 또는 차단 환경에서 동작하지 않을 수 있습니다.

## 구현 방법

- HTML/CSS/JavaScript만 사용, 빌드·서버 불필요
- Open-Meteo의 16일 예보 / 자동 현지 시간대(`timezone=auto`)
- 모바일 우선 반응형 UI
- 로컬 IndexedDB 사진·피드백 저장
- 로컬스토리지 선호도·여행 짐 체크 상태 저장
- PWA 매니페스트와 정적 자산 캐시 서비스워커
- 규칙 로직 `logic.js`, 화면·API 동작 `app.js`

날씨 기반 옷 추천은 검증 전의 **참고용 경험칙**입니다. 실제 체감은 개인·제품별 차이가 크며, 눈·폭염·강풍 등의 위험 기상에서는 안전 공지와 공식 예보를 우선하세요.

## 이후 공개 서비스에서 필요한 작업

이메일 일회용 인증, 서버 DB·사진 저장소, 이미지 판별 및 부적합 사진 격리, 신고/차단/삭제 요청, 기기 간 동기화, 언어별 UX, 이용약관/개인정보처리방침, API 상업 라이선스를 추가해야 합니다. GitHub Pages 자체는 서버 코드를 실행하지 않습니다.
